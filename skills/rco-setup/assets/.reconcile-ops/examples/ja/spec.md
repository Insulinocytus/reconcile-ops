# 仕様: ToDo 項目 CRUD

## 参照元ドキュメント

- [基本的な ToDo 管理](../../docs/goals/G-000001.md)
- [ToDo Web アプリ](../../docs/requirements/todo-web-app.md)

## 目的

実装前に、ToDo 項目の作成、完了、削除の基本設計を定義する。この仕様では、項目の入力、状態遷移、削除、ユーザー向けフィードバックを支えるために必要なコードレベルの設計に焦点を当てる。

## 挙動

- ユーザーは短いタイトルを送信して新しい ToDo 項目を作成する。
- システムは永続化する前にタイトルが空でないことを検証する。
- ユーザーは既存の ToDo 項目を完了済みにできる。
- ユーザーは既存の ToDo 項目を削除できる。
- 削除された項目はアクティブリストから除去される。

## 責務範囲

- ToDo CRUD フローは、項目の作成、完了の切り替え、削除、およびメモリまたは永続化ストレージを扱う。
- ToDo CRUD フローは、ユーザーアカウント、チーム共有、期限、リマインダー、カレンダー連携を扱わない。

## インターフェース

- `POST /todos`
  - Input: title string.
  - Success: generated id を持つ作成済み ToDo 項目。
  - Failure: タイトルが空の場合のバリデーションエラー。
- `PATCH /todos/{id}`
  - Input: completed boolean.
  - Success: 更新済み ToDo 項目。
  - Failure: id が存在しない場合の not-found エラー。
- `DELETE /todos/{id}`
  - Success: 削除の確認。
  - Failure: id が存在しない場合の not-found エラー。

## データコントラクト

- ToDo 項目は空でないタイトル文字列を必須とする。
- ToDo 項目は、生成された一意の id、デフォルト false の completed ブール値、および created-at タイムスタンプを持つ。
- 完了状態と削除状態は相互排他である：同じ項目が完了と削除の両方になることはない。

## バリデーションルール

- タイトルは必須であり、空または空白のみであってはならない。
- 切り替えおよび削除操作には、有効な既存項目の id が必要である。

## エラーハンドリング

- 空のタイトルはバリデーションエラーを表示する。
- 存在しない項目 id に対する操作は not-found エラーを返す。
- 予期しない永続化エラーでは、安全な汎用エラーを返し、アプリケーションログで確認できるようにする。

## 検証方法

- 空のタイトルでバリデーションエラーが発生することを確認する。
- 有効なタイトルで項目を作成した場合に項目が永続化されることを確認する。
- completed の切り替えで項目の状態が変わることを確認する。
- 項目の削除でアクティブリストから除去されることを確認する。
- 存在しない id に対する操作で not-found エラーが返されることを確認する。
