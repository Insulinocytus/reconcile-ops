# 规格说明：待办事项 CRUD

## 来源文档

- [基础待办事项管理](../../docs/goals/G-000001.md)
- [待办事项 Web 应用](../../docs/requirements/todo-web-app.md)

## 目的

在实现前定义待办事项创建、完成和删除的基础设计。本规格说明聚焦于支持条目录入、状态切换、移除和面向用户反馈所需的代码级设计。

## 行为

- 用户提交简短标题以创建新的待办事项。
- 系统在持久化之前校验标题非空。
- 用户可以将已有待办事项标记为已完成。
- 用户可以删除已有待办事项。
- 已删除的待办事项从活跃列表中移除。

## 边界

- 待办事项 CRUD 流程负责条目创建、完成切换、删除以及内存或持久化存储。
- 待办事项 CRUD 流程不负责用户账号、团队共享、截止日期、提醒或日历集成。

## 接口

- `POST /todos`
  - 输入：标题字符串。
  - 成功：携带生成 id 的已创建待办事项。
  - 失败：标题为空时的校验错误。
- `PATCH /todos/{id}`
  - 输入：completed 布尔值。
  - 成功：已更新的待办事项。
  - 失败：id 不存在时的未找到错误。
- `DELETE /todos/{id}`
  - 成功：删除确认。
  - 失败：id 不存在时的未找到错误。

## 数据契约

- 待办事项要求非空标题字符串。
- 待办事项具有生成的唯一 id、默认为 false 的 completed 布尔值以及 created-at 时间戳。
- 已完成和已删除状态互斥：一个条目不能同时处于已完成和已删除状态。

## 校验规则

- 标题为必填，且不得为空或纯空白。
- 切换和删除操作需要有效的已有条目 id。

## 错误处理

- 空标题显示校验错误。
- 对不存在的条目 id 的操作返回未找到错误。
- 意外的持久化错误返回安全的通用错误，并应能通过应用日志观测到。

## 验证方法

- 验证空标题产生校验错误。
- 验证使用有效标题创建条目后条目被持久化。
- 验证切换已完成状态会改变条目状态。
- 验证删除条目会将其从活跃列表中移除。
- 验证对不存在的 id 的操作返回未找到错误。
